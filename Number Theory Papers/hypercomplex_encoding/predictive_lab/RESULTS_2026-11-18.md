# November 18, 2026 — causal hypercomplex predictive encoding

**Question tested:** Can actual higher-dimensional imaginary-algebra multiplication of previously decoded blocks yield a prediction whose residual compresses better than linear, XOR, pointwise or conventional compressors?

**Conclusion:** Not on the six natural/derived files tested. On a separately and deliberately Cayley-Dickson-generated synthetic sequence, yes, a small but independently verifiable saving occurs against matched models; it is not evidence of a real-world general-purpose advantage.

These residual-only numbers use the exact same Zstd9 backend and the exact same suffix lengths; they exclude the shared prefix and are **diagnostics**, not complete codec sizes. Natural files already contain useful character/dictionary structure; the proposed residual mapping disrupts it. The synthetic CD recurrence includes a real past-block bilinear dependency, so its residual becomes smaller than the comparable non-CD models.

The constructed CD source is defined in `benchmark.py` using seed 20261118 and 1,024 blocks of 16 bytes, with the next block generated by a stable, clipped combination of its previous blocks, the CD bilinear product, and injected Gaussian noise. The coefficients were selected for a useful illustrative control; this is **not** a prespecified statistical test and not real-world data.

## Matched-capacity ablations

Each learned model has the same first three scalar coefficients; the CD, pointwise, XOR-convolution and cyclic-convolution variants each add exactly one learned nonlinear coefficient. For the CD synthetic source, complete Brotli11-framed sizes were 12,335 B (CD), 12,609 B (linear), 12,609 B (XOR convolution), 12,612 B (pointwise), 12,611 B (cyclic). On the natural source files, CD was not the winner among these controls.

## Dimensional sensitivity

An *exploratory* exhaustive D=4,8,16,32,64 comparison showed the **best CD prediction was larger than the best linear AR2** on each of the six natural/derived files, even when each was allowed an oracle choice of D. This is a diagnostic, not a valid deployable tuning protocol. Full dimensions and sizes are in `results/dimension_sweep.csv`.

## Performance and limits

These are short-run CPU/Numba/Python prototypes. For example, algebra source D=16 had ~49.8 ms CD encode versus ~33.4 ms direct Brotli11; CD decode took ~2.2 ms versus ~0.08 ms Brotli11. Timings include model fitting and frame construction but exclude initial Numba JIT warmup. Single-repeat or short repeats are **not stable hardware rankings**. No SIMD/GPU kernels were implemented; no cross-machine memory ceiling is claimed.

A prediction advantage is different from an entropy advantage. More general future models (learned quaternion orientation propagation, nonlinear context interaction with real sensor state) remain untested. The evidence does not justify claiming competitive general-purpose compression.

## Reproduce

```sh
cd 'Number Theory Papers/hypercomplex_encoding'
python -m unittest -v predictive_lab.test_predictor
python -m predictive_lab.benchmark --backend brotli11 --out /tmp/hc-predictive-brotli --repeats 2
python -m predictive_lab.benchmark --backend zstd9 --out /tmp/hc-predictive-zstd --repeats 2
python -m predictive_lab.sensitivity --out /tmp/hc-predictive-dimensions
```

The historical results under `results/` are snapshots from the experiment; rerun before claiming timing equivalence on another machine. Data are source files already versioned in the repository, plus explicitly named deterministic synthetic controls.
